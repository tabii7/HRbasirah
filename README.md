# Basirah HR Portal

Full-stack HR portal: employee directory, leaves with doctor-slip uploads, salary slips with proration, reference letters with PDF generation, and role-based access (admin, hr, manager, general_manager, employee).

- **Backend:** Node.js + Express + SQLite (`better-sqlite3`), JWT auth, multer uploads, pdfkit
- **Frontend:** React 19 + Vite + React Router + Axios + lucide-react

## Local development

Prereqs: Node.js 20+ and npm.

```bash
# 1. Install dependencies
cd server && npm install
cd ../client && npm install

# 2. Configure env files (defaults are fine for local dev)
cp server/.env.example server/.env
cp client/.env.example client/.env

# 3. Run both apps in two terminals
cd server && npm run dev     # http://localhost:5000
cd client && npm run dev     # http://localhost:5173
```

Default admin login (seeded on first run): `admin@basirah.local` / `admin123`.

## Environment variables

### Server (`server/.env`)

| Var | Default | Notes |
|-----|---------|-------|
| `PORT` | `5000` | Render injects this automatically. |
| `JWT_SECRET` | dev placeholder | **Required in production.** Use a long random string. |
| `CLIENT_URL` | _(empty = allow all)_ | Comma-separated allowed origins for CORS. |
| `ADMIN_EMAIL` | `admin@basirah.local` | Seeded admin email. |
| `DATA_DIR` | `server/data` | Where `hr.db` lives. Point to a persistent disk in prod. |
| `UPLOADS_DIR` | `server/uploads` | Where uploaded files live. Point to a persistent disk in prod. |
| `LOGO_PATH` | auto-detect | Path to logo PNG used on PDFs/slips. |
| `SMTP_*`, `MAIL_FROM`, `ADMIN_NOTIFICATION_EMAIL` | unset | Optional, for reference-letter email notifications. |

### Client (`client/.env`)

| Var | Default | Notes |
|-----|---------|-------|
| `VITE_API_BASE` | `http://localhost:5000` | Backend base URL (no trailing slash). |

## Health check

`GET /api/health` returns `{ status: "ok", uptime }` and is used as the Render health check.

## Deploying to Render

This repo includes a `render.yaml` Blueprint that provisions both services from a single deploy:

1. Push the repo to GitHub.
2. In Render, **New + → Blueprint** → connect this repo.
3. Render will create:
   - **basirah-api** — Node web service (`server/`) with a 1 GB persistent disk mounted at `/var/data` for `hr.db` and uploads.
   - **basirah-web** — Static site built from `client/` (`npm run build`, publishes `client/dist`) with SPA rewrites.
4. Set the env vars Render marks as `sync: false`:
   - On `basirah-api`: `CLIENT_URL` = your frontend URL, e.g. `https://basirah-web.onrender.com`
   - On `basirah-web`: `VITE_API_BASE` = your API URL, e.g. `https://basirah-api.onrender.com`
5. Trigger a redeploy on the static site after setting `VITE_API_BASE` (Vite envs are baked at build time).

`JWT_SECRET` is auto-generated by Render. The default admin user is seeded on first boot.

> **Note:** The free Render Node plan does not include persistent disks. Either upgrade the API service to a starter plan (which is required for the `disk` block in `render.yaml`), or remove the `disk` block and accept that `hr.db` and uploads will reset on each deploy.

## Security notes

- Change `JWT_SECRET` in production.
- Restrict `CLIENT_URL` to your real frontend origin(s) in production.
- The seeded admin uses a default password — change it after first login.
